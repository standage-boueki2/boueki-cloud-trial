# 3回目の評価（最終版の確認採点）— 全担当共通

2回目（`findings2/`）で見つかった課題を直した最終版ができています。3回目は、**最終版** を同じペルソナで操作し、(1) 2回目の課題が直ったかを1件ずつ確かめ、(2) 3人の総合点と画面ごとの点を付け直します。目標は「どの人も 5点」。届かない所は、再現できる事実で残します。

## 見る版
- 最終版：**`BASE=http://127.0.0.1:8814/`**（`lib.cjs` は環境変数 BASE を見る。必ず付ける）
- 2回目のときの版：`http://127.0.0.1:8813/`
- 道具：`scratchpad/tools/README.md`（画面のキー・この環境だけの事情・採点の決まり）、ペルソナの定義 `scratchpad/tools/BRIEF.md`

## 進め方
1. 自分の業種の 2回目の結果 `scratchpad/findings2/<ID>.json`（ペルソナ・点数・`issues`＝新しい課題・`recheck` で partial／open だったもの）を読む。ペルソナは同じ人。
2. **2回目の課題（`<ID>-N..`）と、partial／open だった1回目の課題を、同じ手順で 8814 で確かめ直す**：`fixed`／`partial`／`open`／`worse` と、見た事実（画面の文言）を1行。
3. **P2・P3 の主な流れを通し直す**：バイヤーを足す → 商談を記録 → 案件一覧に出る → 案件の詳細 →「書類をつくる」（見積書 PI・請求書 CI・梱包明細）→ 建値を変える → タスク・受信箱・分析の数字。P1 は資料の登録（`L.registerByUpload`）から「次は」だけで最後まで。
4. 2回目に「開いて読んだだけなので 4」とした画面は、今回は**主要な操作を1〜2つ実際に行って**から点を付ける（目標と道筋・受信箱・会議メモ・依頼ページ・ドキュメント・契約書関連・用語集・取り込んだ情報・ゴミ箱・受注・請求・入金 など）。操作して問題が無ければ 5 を付けてよい。問題があれば課題にする。
5. 点は事実で付ける。甘くも辛くもしない。5＝その人の目的が迷わず達成でき、誤り・表示崩れ・数字の食い違いが無い。この環境だけの事情（AI 未接続・同期サーバーが代役・外への通信が止められている・「開発中」と明記された画面が開発中であること自体）は減点しない。ただし、それを理由に行き止まりになる・案内が無いなら課題。
6. 新しく見つけた課題は `<ID>-M01` から。証拠（画面の文言の引用か画像の絶対パス）のない課題は載せない。

## 守ること
- 事実だけ。作業は `scratchpad/agents3/<ID>/` の中だけ。`tools/`・`build/`・`fix/`・リポジトリ・サーバーには触らない。git の操作はしない。
- 機械が混んでいる。ブラウザは同時に1つ・1回 90秒以内。画像は要所だけ（全部で 30 枚まで）。
- スクリプトは Write の道具で書く（Bash のヒアドキュメントで JS を書くと止められる）。出力は `cut -c1-300` で短く。
- 途中で止まっても残るよう、ペルソナ1人が終わるごとに json を書き出す。
- 最後の返事は短く：ペルソナ別の総合点（2回目→今回）、2回目の課題の結果の数（fixed／partial／open／worse）、残っている課題を重い順に全部（番号・画面・一行）、提出ファイルのパス。
