# 4巡目の直し（3回目の評価で残ったものを全部つぶす）— 担当共通

3回目の評価（`findings3/`）では、36人のペルソナが全員 4点でした（5点は 0人）。そのあと 3本の直し（r3a・r3b・r3c）が入りました。
あなたの仕事は、**自分の領域に残っている課題を、今の最新版で1件ずつ確かめ、まだ起きるものを全部直すこと**です。目標は「どのペルソナも 5点」。

## 先に読む
1. `scratchpad/fix/FIX_BRIEF.md` … アプリの作り・層の書き方・CSP・守ること（**必ず守る**。今の関数は包むだけ。機能・欄を消さない。架空の数字・事実を作らない）。
2. `scratchpad/tools/README.md` … `lib.cjs` の使い方、この環境だけの事情。
3. 自分の割り当て `scratchpad/fix/<AREA>/issues.json` … `issues`（`kind: r3-new` は3回目の新しい課題、`r3-recheck` は3回目でも partial／open だった前の課題）と、`to5_all`（各ペルソナが「5点にはあと何が要るか」と書いたもの。自分の領域に当たるものは拾う）。
4. 3巡目の直しの報告 `scratchpad/fix/r3a/notes.txt`・`r3b/notes.txt`・`r3c/notes.txt` … **すでに直ったもの・「残した」もの・「未確認」のもの**が書いてある。直ったと書いてあるものは、最新版で1回見て確かめるだけでよい。「残した」「未確認」は、あなたが引き取る。

## 見る版・組み立て
- 最新版（r3a・r3b・r3c 入り）：`http://127.0.0.1:8811/`（刷新版）。3回目の評価のときの版：`http://127.0.0.1:8814/`。
- 自分の層：`fix/<AREA>/src/logic_v2192<AREA>.ts`（本体）と `rd_v92<AREA>.js`・`rd_v92<AREA>.css`（刷新版）。**この3つだけ書く**。共通の層（`build/src/`）は読むだけ。
- 組み立て：`$SP/fix/mkfix.sh <AREA>` → `fix/<AREA>/work/redesign`。そのあと `cp -r $SP/work/redesign/rm $SP/fix/<AREA>/work/redesign/ 2>/dev/null`（rm/ は自分で写す）。自分のポートで配る。
- あなたの層は、ほかの全部の層より**後**に読み込まれる（取り込むとき `z5…` の名前にする）。`mkfix.sh` でも共通の層の後ろに付く。
- 確かめ：直す前に 8811 で再現 → 直した後に自分のポートで同じ手順。最後に `BASE=http://127.0.0.1:<PORT>/ node $SP/tools/regress.cjs food,daily,machine,fwd`（ALL OK になること）。

## 進め方
- 重い順（major → minor → polish）。同じ原因はまとめて直す。**時間切れで残さない**よう、調べに 10分以上かかる課題は後回しにして、先に全体を1周する。
- データが無いもの（ひな形の無い品目の関税率・カテゴリー別のバイヤー数 など）は作らない。「要確認」と出どころへの入口を、どの画面でも同じ言い方でそろえる所まで。
- 別ファイル（`guide/`・`cs.html`）と同期サーバーは直せない。アプリの側の案内（文・入口）で行き止まりを無くす所まで。
- 新しい文は `M(ja,en,zh,es)` の形か `I18N.dict` に英・中・西を足す（r3c の層 `build/src/logic_v2192z4r3c.ts` の頭にやり方がある）。日本語のままの文を増やさない。
- 見本のデータ（商談の記録・支払条件・日付など）の食い違いは、表示の側で直せるなら直す。見本の保存の形は壊さない。

## 守ること
- 作業は `fix/<AREA>/` の中だけ。`tools/`・`build/`・ほかの担当のフォルダ・リポジトリ・8801〜8814 のサーバーには触らない。git の操作はしない。
- ブラウザは同時に1つ・1回 90秒以内。スクリプトは Write の道具で書く（Bash のヒアドキュメントで JS を書くと止められる）。出力は `cut -c1-300`。`curl` は必ず `-o /dev/null`。index.html を grep するときは `cut -c1-300`。
- 途中で止まっても残るよう、報告 `fix/<AREA>/notes.txt` を課題を1つ片づけるごとに書き足す（.md は道具が止めることがあるので .txt）。

## 提出
- 層のファイル（`mkfix.sh` が通り、回帰が ALL OK）。
- `fix/<AREA>/notes.txt`：課題の番号ごとに「直した（画面で確認済み）／直した（未確認）／すでに直っていた／残した（理由）」と、どう直したか・どう確かめたかを1〜2行。
- 最後の返事は短く：件数（直した・すでに直っていた・残した）、残したものの番号と理由、層のファイルのパス、ほかの画面に効く変更があればその注意。
