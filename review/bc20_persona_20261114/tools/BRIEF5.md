# 5回目の評価（最終版の確認採点）— 全担当共通

4回目（`findings4/`）は 36人中 14人が 5点、22人が 4点でした。残った課題に 3本の直し（r5a・r5b・r5c）を入れた最終版ができています。
5回目は、**最終版** を同じペルソナで操作し、(1) 4回目に残った課題が直ったかを1件ずつ確かめ、(2) 総合点を付け直します。**4回目に 5点だった人も、直しで壊れていないかを主な流れで確かめて点を付け直します**。

## 見る版
- 最終版：**`BASE=http://127.0.0.1:8816/`**（必ず付ける）。4回目のときの版：`http://127.0.0.1:8815/`。
- 道具と決まり：`scratchpad/tools/README.md`・`BRIEF.md`（ペルソナ）・`BRIEF4.md`（**点の付け方・守ること・提出の形は 4回目と同じ**。BRIEF4.md の「進め方 4」をもう一度読む）。

## 進め方
1. 自分の4回目の結果 `scratchpad/findings4/<ID>.json` を読む。4回目のスクリプトは `scratchpad/agents4/<ID>/` にある（写して使ってよい）。
2. 4回目の課題（`<ID>-Q..`）と partial／open だった前の課題を、同じ手順で 8816 で確かめ直す：`fixed`／`partial`／`open`／`worse` と見た事実を1行。
3. 今回の直しで変わった所を、自分のペルソナの流れの中で必ず通る：
   - 右上の「次は」だけで、登録 → 国を確定 → 規制 → 営業資料 → バイヤー開拓 → 商談 まで進めるか（行き来・行き止まりが無いか）。
   - 「受注内容を編集」に足された「仕向港」「出港の予定日（ETD）」の欄と、書類の点検（仕向港・期限の警告）。
   - 分析・レポートの「累計受注金額」「見積金額」（開く案件を替えても変わらないか・記録と合うか）。
   - 目標と道筋の ✓（やった手順だけに付くか）。
   - 入り直したとき（ブラウザを閉じて同じ profile で開く）に、ホーム（案件一覧）から始まり、商品・案件・記録が残っているか。3回以上。
   - 物流会社：見積受信箱の表が枠に収まるか。多言語：登録直後の今日やること・タスク・受信箱・ログイン画面。
4. 点は事実で付ける。甘くも辛くもしない（BRIEF4.md の 4 のとおり）。新しい課題は `<ID>-R01` から。証拠の無い課題は載せない。

## 提出物
`scratchpad/findings5/<ID>.json`（形は同じ。`base` は "8816"、ペルソナは `overall_r4` と `overall`、`to_5`）と `<ID>.txt`。作業は `scratchpad/agents5/<ID>/` の中だけ。
最後の返事は短く：ペルソナ別の総合点（4回目→今回）、4回目の課題の結果の数、残っている課題を重い順に全部（番号・画面・一行・誰が引っかかるか）、提出ファイルのパス。
