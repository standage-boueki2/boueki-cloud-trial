# 6回目の評価（最終版の確認採点）— 全担当共通

5回目（`findings5/`）は 36人中 15人が 5点、21人が 4点でした。残った課題に 4本の直し（r6a・r6b・r6c・r6x）を入れた最終版ができています。
6回目は、**最終版** を同じペルソナで操作し、(1) 5回目に残った課題が直ったかを1件ずつ確かめ、(2) 総合点を付け直します。**5回目に 5点だった人も、直しで壊れていないかを主な流れで確かめて点を付け直します**。

## 見る版
- 最終版：**`BASE=http://127.0.0.1:8817/`**（必ず付ける）。5回目のときの版：`http://127.0.0.1:8816/`。
- 道具と決まり：`scratchpad/tools/README.md`・`BRIEF.md`（ペルソナ）・`BRIEF4.md`（**点の付け方（進め方 4）・守ること・提出の形は BRIEF4.md のとおり**）。

## 進め方
1. 自分の5回目の結果 `scratchpad/findings5/<ID>.json` を読む。5回目のスクリプトは `scratchpad/agents5/<ID>/` にある（写して使ってよい）。
2. 5回目の課題（`<ID>-R..`）と partial／open だった前の課題を、同じ手順で 8817 で確かめ直す：`fixed`／`partial`／`open`／`worse` と見た事実を1行。
3. 今回の直しで変わった所を、自分のペルソナの流れの中で必ず通る：
   - 右上の「次は」（と、それが光らせたボタン）だけで、登録 → 国を確定 → 規制 → 営業資料 → バイヤー開拓（リストを作る → 相手を選ぶ → 送る／自社のバイヤーに入れる）→ 商談を記録、6/6 まで。足踏み・行き来・行き止まりが無いか。6/6 のあとのホーム。
   - 分析・レポートとホームの「累計受注金額」「見積金額」「見積を出している案件」「直近7日」「どこまで進んだか」、商談・バイヤーの札、内訳の窓：商談中の記録だけ／見積提示＋見積書／受注を記録 → 書類 →「受注内容を編集」で数量・単価を直す、のそれぞれで、数字が互いに合うか・二重に出ないか・開く案件を替えても変わらないか。US$ 以外の通貨の見積。
   - 目標と道筋の ✓ と根拠の文（受注を記録したあとを含む。やった手順だけに付くか）。
   - 書類：取引条件の港を途中で変える・日本語の地名・FOB で仕向港なし、のときの見積書・請求書・梱包明細・船積依頼書（S/I）・荷印・点検の仕向港。出港の予定日（過ぎた日・希望着荷より後の到着）。S/I の梱包数・重量が梱包明細と合うか。
   - 入り直し（閉じて同じ profile で開く・3回以上）で、ホームから始まり、商品・案件・記録が残るか。
   - 物流会社：見積受信箱の表、AI物流マンの答え、「回答の金額を直す」の案内。多言語：「次は」の名前、「書類を足す」の選択肢、物流会社の画面。
4. 点は事実で付ける。甘くも辛くもしない（BRIEF4.md の進め方 4 のとおり：5＝その人の目的が迷わず達成でき、その人の使う範囲に誤り・表示崩れ・数字の食い違いが無い。polish だけなら 5。minor 以上が残れば 4。この環境だけの事情・アプリに無いデータ〔案内があれば〕・別ファイルのガイドは減点しない）。新しい課題は `<ID>-S01` から。証拠の無い課題は載せない。

## 提出物
`scratchpad/findings6/<ID>.json`（形は同じ。`base` は "8817"、ペルソナは `overall_r5` と `overall`、`to_5`）と `<ID>.txt`。作業は `scratchpad/agents6/<ID>/` の中だけ。
守ること：Bash のヒアドキュメントで JS を書かない（Write の道具で）。出力は短く切る。ブラウザは同時に1つ・1回 90秒以内。画像は 20枚まで。git・リポジトリ・サーバー・ほかのフォルダには触らない。
最後の返事は短く：ペルソナ別の総合点（5回目→今回）、5回目の課題の結果の数、残っている課題を重い順に全部（番号・画面・一行・誰が引っかかるか）、提出ファイルのパス。
