# 2回目の評価（直した版の採点）— 全担当共通

1回目（11/14）は、21.91 の刷新版を P1（貿易素人）中心に見たところで止まりました。その後、見つかった課題を直した版（21.92 の続き）ができています。
2回目は **直した版** を、同じ業種の **3人のペルソナ全員** で、全画面・全機能について採点し直します。目標は「どの人も 5点満点」。届かない所は、**再現できる事実**で残します。

## 見る版
- 直した版：`BASE=http://127.0.0.1:8813/`（`lib.cjs` は環境変数 BASE を見る。**必ず 8813 を指定**）
- 直す前（くらべたいとき）：`http://127.0.0.1:8801/`
- 道具：`scratchpad/tools/README.md`・1回目の決まり `scratchpad/tools/BRIEF.md`（ペルソナの定義・守ること・提出の形はそのまま）

## 進め方
1. 1回目の自分の結果 `scratchpad/findings/<ID>.json`（ペルソナ・点数・課題）を読む。ペルソナは同じ人を使う（無ければ BRIEF.md の定義で決める）。
2. **1回目の課題を1件ずつ確かめ直す**：同じ手順を 8813 で行い、`fixed`（直った）／`partial`（一部）／`open`（そのまま）／`worse`（悪くなった）を付け、見た事実（画面の文言）を1行書く。
3. **P2（少し経験者）と P3（商社経験豊富）で全画面を通す**（1回目は P1 が中心だった）。P2 は引き合い→見積→書類→タスクを自分で回す流れ、P3 は専門用語のまま速く・数字の根拠・建値/決済/書類の正確さ・一覧性・書き出し・権限・分析。P1 も最初の画面から通し直す（`L.enter(page, { firstRun: true })`）。
4. その業種の商品は、**業種サンプル**（`L.loadSample`）と、**資料の読み取り**（`scratchpad/files/` の自分の業種の xlsx を `L.registerByUpload`）の両方で確かめる。
5. 全画面×3人の点数を埋める（5 を付けるなら、何を操作して何が良かったかを `exercised` に書く。甘く付けない・辛くもしない。5 に届かない画面は理由を `to_5` に）。
6. 新しく見つけた課題は `<ID>-N01` からの番号で（1回目の番号と分ける）。証拠のない課題は載せない。この環境だけの事情（外への通信が止められている・AI が未接続・はじめての窓が毎回出る など README にあるもの）は課題にしない。

## 守ること
- 事実だけ。操作して見たものだけを書く。5 を付けるのも、5 に届かないとするのも、根拠を書く。
- 作業は `scratchpad/agents2/<ID>/` の中だけ。`tools/`・`build/`・`fix/`・リポジトリ・サーバーには触らない。git の操作はしない。
- 機械が混んでいる。ブラウザは同時に1つ・1回 90秒以内。画像は要所だけ（1ペルソナ 10〜15 枚まで）。
- Bash のヒアドキュメントで JS を書くと安全確認に止められる。スクリプトは Write の道具で書く。
- 途中で止まっても残るよう、ペルソナ1人が終わるごとに json を書き出す。
- 最後の返事は短く：ペルソナ別の総合点（前回→今回）、1回目の課題の結果の数（fixed／partial／open／worse）、残っている重い課題の上位 8件（番号・画面・一行）、提出ファイルのパス。
