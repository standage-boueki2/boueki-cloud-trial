■ 5. 残したもの（理由）
  1. 英語の「更新」の重さ（全版）：本体の訳の処理（i18nElKey・hit）が読み込みの間に約1.4秒（x1）。CPU 1/4 では 30秒の間 long task が続く。
     本体の訳の仕組み（文字の節ごとに辞書と形を当てる）を変えないと減らせない。r9p の「残したもの」の本体の重さと同じ扱い。
  2. 「読み込み中…」の文字は、html の lang が付く（本体のスクリプトの I18N の初期化）まで日本語。英語の利用者には x1 で約1.5秒、x4 で約6秒「読み込み中…」が出て、
     そのあと「Loading…」になる（m/splash.cjs）。r9p の head の CSS は言語を知る手段が無い（保存の言語は JS でしか読めない）。日英併記にするかは決めが要る。
  3. 見出しが k-slim の画面の「点線の言葉は…」の説明の文は、21.93 の設計で文字の大きさ 0（1440・390 とも、8819 から）。目に見えるのは 390 のリンクだけ。
     「説明の行を見せる」なら 21.93 の rd_case.css の k-slim の指定を変える決めが要る（今回は r9b の意図どおりのまま）。
     あわせて、390 のホームのこの（見えない）文が 8819・8904 は「押すと説明が出ます」、8901・8811 は「押すか、マウスを乗せると」（文字の大きさ 0 なので見た目の差なし）。
  4. 書類の画面で、受注の窓・知らせの「（想定）UAEの輸入商社」など見本の相手の名前（データ）は日本語のまま（値）。
  5. 英語の単位は「1 units」のように数で変えない（r9c の単位の訳と同じ）。
  6. 1440 で画面を移った直後に、見出しの下の「📖 用語集」のリンクが一瞬見えることがある（r9b の印 k-r9b-glside は、左の帯の箱を 21.93 の misc の層が描き直すと
     60ms 後に見直す。その間に取った文字に「用語集」が入る。jadump の food で 2 画面）。数十 ms の揺れで、r9b の層の作り（箱の描き直しを見て付け直す）どおり。
  7. 規制を調べるの業種の観点の本文（中 5・西 12 行）は英語のまま（r9c が残したものと同じ）。
